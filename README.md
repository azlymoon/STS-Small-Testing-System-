# STS — Small Testing System

Небольшая тестирующая система для уроков программирования на C++. Поднимается за несколько минут
на ноутбуке преподавателя: ученики заходят по ссылке, входят по ФИО (без регистрации), сдают решения,
код компилируется и проверяется на тестах в изолированном Docker-контейнере, результат по каждому
тесту виден сразу. Преподаватель видит всё в админке и на живом дашборде.

Сделана как быстрая замена LMS на время её недоступности, рассчитана на класс до ~40–80 человек.

## Возможности

**Ученику**
- Вход по ФИО, без паролей и почты; список уроков разбит по вкладкам («1 год», «2 год», …).
- Условие задачи с примерами, отправка кода текстом или файлом `.cpp`.
- Вердикт через несколько секунд; по каждому тесту — входные данные, правильный ответ, вывод программы, stderr.

**Преподавателю**
- Уроки: импорт задач прямо из `.docx` (условия, код-заготовки, таблицы примеров), ручное редактирование.
- Тесты: zip-архивом, по одному, или генератором по эталонному решению (`tools/gen_tests.py`).
- Группы: несколько групп могут заниматься одновременно; посылки помечаются группой; отчёт
  «ученики × уроки» по группе и выгрузка в CSV (Excel).
- Живой дашборд: ученики онлайн, очередь, время проверки, CPU/память/Docker, таблица «ученики × задачи»,
  статистика по задачам, «нужна помощь» (кто застрял), лента посылок.
- Все посылки и код, перепроверка, объединение/переименование учеников, перенос посылок между группами.
- Публичная ссылка через Cloudflare Tunnel (без белого IP и настройки роутера) + короткая ссылка clck.ru
  и страница `/screen` для проектора.

## Требования

- macOS или Linux
- Python 3.11+ (проверено на 3.14)
- Docker (Docker Desktop / OrbStack / Docker Engine), запущенный
- `cloudflared` — для публичной ссылки (`brew install cloudflared`, или см. сайт Cloudflare)
- `g++` — только для генерации тестов (`tools/gen_tests.py`); на macOS есть в Xcode Command Line Tools

## Установка

```bash
git clone https://github.com/azlymoon/STS-Small-Testing-System-.git sts
cd sts
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
docker build -t mshp-cpp sandbox            # образ песочницы (Alpine + g++); run.sh соберёт его и сам
.venv/bin/python tools/seed_demo.py         # необязательно: демо-урок /lesson/demo с двумя задачами
```

## Запуск

```bash
./start.sh
```

Скрипт запускает сервер и туннель и печатает:

```
 ДЛЯ УЧЕНИКОВ:       clck.ru/xxxxxx
 Показать на экране: https://xxx.trycloudflare.com/screen
 Полная ссылка:      https://xxx.trycloudflare.com
 Админка:            https://xxx.trycloudflare.com/admin   (пароль: data/admin_password.txt)
```

- Остановка — `Ctrl+C`. Если что-то осталось работать: `pkill -f "uvicorn app.main:app"; pkill -f "cloudflared tunnel"`.
- Ссылка `trycloudflare` **меняется при каждом перезапуске** туннеля — раздайте ученикам новую
  (короткая создаётся автоматически; если clck.ru недоступен, показывается полная).
- Перезапустить только сервер (после обновления кода), не меняя ссылку:
  `pkill -f "uvicorn app.main:app"; nohup ./run.sh > data/server.log 2>&1 &`
- Только локально, без туннеля: `./run.sh` → http://127.0.0.1:8000
- На macOS сервер запускается под `caffeinate`, чтобы ноутбук не уснул. Крышку не закрывайте.

### Пароль администратора

При первом запуске генерируется и сохраняется в `data/admin_password.txt`:

```bash
cat data/admin_password.txt
```

Свой пароль: `ADMIN_PASSWORD='...' ./start.sh`.

## Как пользоваться

### Ученик
1. Открывает ссылку (короткую или полную) → вкладку своего года → урок.
2. Вводит фамилию и имя (одинаково на всех уроках). Если сейчас занимаются несколько групп — выбирает свою.
3. Открывает задачу, вставляет код или прикрепляет `.cpp`, нажимает «Отправить».
4. На странице посылки видит вердикт и все тесты; упавшие тесты раскрыты сразу.

### Преподаватель
1. **Группы** → создать группы (например «1 год · Пн 16:00», год «1 год»).
2. Перед занятием — справа сверху в админке «Сейчас занимаются: + группа». Можно несколько групп сразу:
   тогда ученик при входе выбирает свою. После занятия — «×» у группы или «Закончить» в разделе «Группы».
3. **Уроки** → «Новый урок»: название, вкладка (год), адрес (латиницей, напр. `y1-l05`), файл задач `.docx`.
   Урок доступен по `/lesson/<адрес>`; ученики также видят его в списке на главной.
   Старые уроки можно скрыть (снять «открыт»).
4. В уроке → задача → **тесты**: загрузить zip или добавить вручную (см. ниже).
5. **Дашборд** — следить за занятием в реальном времени. **Группы → группа** — итоговая таблица и CSV.

### Формат `.docx` для импорта
Импортёр (`app/docx_import.py`) рассчитан на документы вида «Задачи / Эксперт / Олимпиадная задача»:
- каждая задача — пункт нумерованного списка 2-го уровня (название задачи);
- разделы — абзацы «Условие», «Формат входных данных», «Формат выходных данных», «Примечания», «Примеры»;
- код-заготовки (моноширинные абзацы без заливки) превращаются в блок кода C++;
- таблица «Входные данные | Выходные данные» → тесты-примеры (видны в условии);
- строка сложности «Простая - Средняя - Сложная - Олимпиадная» (выделенная жирным) → «Сложность: …»;
- блоки только с картинками пропускаются (картинки не импортируются).

После импорта условие можно поправить в админке (Markdown, код — в блоке ```` ```cpp ````).

### Тесты
- **zip-архив**: пары `1.in` + `1.out` (или `.ans`), `01` + `01.a`, `input1.txt` + `output1.txt`; можно в подпапках.
- **вручную** — по одному тесту, с галочкой «показывать в условии как пример».
- **генератором** — для пачки задач: эталонное решение + функция, порождающая входы.
  ```
  tests_src/                       # приватная папка (в .gitignore)
    generators.py                  # TITLES = {key: "Название задачи"}, GENS = {key: функция → список входов}
    <key>/sol.cpp                  # эталонное решение
  ```
  ```bash
  .venv/bin/python tools/gen_tests.py            # все задачи из tests_src/
  .venv/bin/python tools/gen_tests.py key1 key2  # выбранные
  ```
  Эталон сначала проверяется на примерах из условия, затем по каждому входу считается ответ;
  тесты сохраняются в `tests_src/<key>/tests/` и загружаются в базу (не-примеры задачи заменяются).
  Образец набора — `examples/demo/` (`tools/gen_tests.py --set examples/demo`).
- После изменения тестов — «Перепроверить все посылки» на странице задачи.

## Как проверяется решение

- Очередь в SQLite, фоновый воркер, до 8 контейнеров параллельно (`PARALLEL` в `app/judge.py`).
- Компиляция `g++ -std=c++17 -O2`; ограничение времени задаётся на задачу (по умолчанию 1 с).
- Контейнер: без сети, файловая система только для чтения, 256 МБ памяти без swap, 1 CPU, 64 процесса,
  без capabilities, пользователь nobody, лимит размера файлов. После каждого теста завершаются все
  процессы программы (защита от fork-бомб). После 3 превышений времени остальные тесты не запускаются.
- Вердикты: OK, WA, TLE, ML (превышена память), RE, CE, SE (ошибка системы), SK (тест не запускался).
- Ответ сравнивается по токенам (пробелы и переводы строк не важны), дробные числа — с точностью 1e-6.
- Анти-спам: не чаще одной посылки в 5 секунд и не больше 3 непроверенных посылок на ученика.

## Нагрузка

MacBook (11 ядер), доступ учеников через Cloudflare Tunnel:
- 40 одновременных посылок — 40/40 вердиктов верные, все проверены за ~12 с (медиана ожидания ~7 с);
- 80 одновременных — 80/80 верные, ~26 с.

Проверить на своей машине — **на отдельной копии данных**, чтобы не смешивать с настоящими:

```bash
mkdir -p /tmp/sts-test
MSHP_DATA=/tmp/sts-test .venv/bin/python tools/seed_demo.py
MSHP_DATA=/tmp/sts-test PORT=8001 ./run.sh &
MSHP_DATA=/tmp/sts-test .venv/bin/python tools/stress_test.py http://127.0.0.1:8001 40
```

Тест имитирует N учеников с отдельными сессиями (вход → урок → задача → одновременная отправка верных,
неверных, TLE, CE и RE решений → опрос результата) и сверяет вердикты и группы. **Не запускайте его на
рабочем сервере во время занятий** — он создаёт учеников и посылки.

## Настройки

| Что | Где |
|---|---|
| Пароль админки | `ADMIN_PASSWORD` или `data/admin_password.txt` |
| Папка данных (база, секреты, логи) | `MSHP_DATA` (по умолчанию `data/`) |
| Адрес/порт сервера | `HOST`, `PORT` для `./run.sh` |
| Параллельные проверки, память | `PARALLEL`, `MEMORY` в `app/judge.py` |
| Пауза между посылками | `SUBMIT_COOLDOWN` в `app/main.py` |

**Бэкап** — `sqlite3 data/mshp.sqlite3 ".backup backup.sqlite3"` (или скопировать файл при остановленном сервере).

## Постоянный адрес / сервер

- Свой домен в Cloudflare + именованный туннель (`cloudflared tunnel create …`) — ссылка перестанет меняться.
- Или VPS: тот же код и Docker, `HOST=0.0.0.0 ./run.sh` за nginx/Caddy с HTTPS.

## Ограничения

- Вход по ФИО без пароля — ученик может войти под чужим именем (осознанный компромисс ради простоты).
- Только C++ (другие языки добавляются в `sandbox/` и `app/judge.py`).
- Картинки из `.docx` не переносятся.
- Один процесс сервера и SQLite — рассчитано на класс, а не на тысячи пользователей.

## Структура

```
app/main.py            страницы ученика и админки (FastAPI)
app/judge.py           очередь и запуск проверки в Docker
app/groups.py          группы, отчёты, CSV
app/dashboard.py       дашборд и его API
app/db.py              схема SQLite и миграции
app/docx_import.py     разбор .docx с задачами
app/templates/         Jinja2-шаблоны (без сборки фронтенда)
sandbox/               Dockerfile и скрипт песочницы
tools/gen_tests.py     генерация тестов по эталону
tools/seed_demo.py     демо-урок
tools/stress_test.py   нагрузочный тест
examples/demo/         образец набора задач для генератора
start.sh / run.sh      запуск с туннелем / только сервер
data/                  база, пароль, секрет, логи — в git не попадает
tests_src/             ваши эталоны, генераторы и тесты — в git не попадает
```

Задачи, тесты и решения курса в репозиторий не входят: они хранятся только в `data/` (база) и `tests_src/`.
